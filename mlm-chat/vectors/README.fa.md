# نمونه‌های آزمون مرجع

هر پیاده‌سازی قرارداد MLM CHAT باید این بایت‌ها را عیناً بسازد. همه با کلیدهای ساختگیِ ثابت ساخته شده‌اند و هیچ کلید واقعی‌ای در آن‌ها نیست.

| فایل | چه چیزی | بند مشخصات |
|---|---|---|
| `identity.json` | نیمهٔ ۳۰ رقمی، شمارهٔ امنیتی ۶۰ رقمی، نام کوتاه | ۲، ۱۴.۱ |
| `card.json` | کارت رو در رو و پیوند دور (CBOR و پیوند)، multiaddr | ۳، ۱۴.۳ |
| `envelope.json` | پاکت متن، رسید «خوانده شد»، `KeyUpdate` | ۵ |
| `frame.json` | قاب پرشده (۲۵۶ و ۱۰۲۴ بایت) و شناسهٔ تأیید | ۶، ۱۴.۵ |
| `sealed.json` | یک `SealedFrame` که با کلید داده‌شده باز می‌شود | ۴، ۶، ۱۴.۶ |
| `beacon.json` | برچسب و نشانهٔ شبکهٔ محلی | ۸، ۱۴.۸ |
| `direct.json` | کلید پیش‌مشترک Noise، ورودی و امضای «سلام» | ۱۴.۷ |

- آزمون: `cargo test --test vectors` در `core/`.
- این فایل‌ها یک بار ساخته شده‌اند و **برای پاس شدن آزمون عوض نمی‌شوند.** اگر یکی غلط است، اصلاحش خودش یک `spec-change` است (قانون `CLAUDE.md`).
- برای Olm نمونه‌ای نیست: جلسهٔ Olm عمداً تصادفی است و vodozemac نمونه‌های خودش را دارد.
- `sealed.json` چون HPKE کلید موقت تازه می‌سازد، فقط «باز کردن» را می‌سنجد.
