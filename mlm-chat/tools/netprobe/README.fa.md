# netprobe: سنجش شبکه برای MLM CHAT (فاز ۰)

برنامهٔ آزمایشی جدایی برای اندروید که روی گوشی واقعی می‌سنجد شبکه‌های ایران چه راهی برای اتصال گوشی‌به‌گوشی باز می‌گذارند (بند ۱۷ برنامه). بستهٔ خودش را دارد (`com.mlmchat.netprobe`) و به MLMVPN یا هیچ اپ دیگری دست نمی‌زند. دستور قدم‌به‌قدم آزمون‌ها و جدول نتیجه در `docs/PHASE0-RESULTS.fa.md` است.

## چه می‌سنجد

| آزمون | چه چیزی | ناظر لازم است؟ |
|---|---|---|
| رفتار NAT، IPv6 و دسترسی | دسترسی به هر درگاه ناظر با TCP و UDP؛ نگاشت UDP و TCP (مستقل یا وابسته به مقصد، حفظ درگاه، یکسان بودن نشانی عمومی نزد دو ناظر)؛ پالایش UDP؛ اتصال TCP ورودی به نگاشت؛ نشانی IPv6 سراسری، خروج و ورود IPv6 | بله (دو ناظر = نتیجهٔ کامل) |
| سرعت تا ناظر | ۱۰ رفت‌وبرگشت و ۱ مگابایت بارگذاری و بارگیری | بله |
| عمر نگاشت | نگاشت UDP بی‌کار چند ثانیه زنده می‌ماند (تا ۵ دقیقه)؛ اتصال TCP بی‌کار چقدر (تا ۲۰ دقیقه). عدد فاصلهٔ «زنده نگه داشتن» و در نتیجه مصرف باتری را معلوم می‌کند | بله |
| UPnP مودم | آیا مودم خانه با UPnP درگاه باز می‌کند، و آیا از بیرون واقعاً می‌رسد | برای وارسی از بیرون |
| اتصال مستقیم دو گوشی | هر نشانی کارت گوشی دیگر (IPv6 سراسری، شبکهٔ محلی، نشانی داخلی اپراتور، نگاشت عمومی) با TCP و QUIC؛ هر دو جهت، چون هر دو گوشی هم‌زمان اجرا می‌کنند | نه |
| سوراخ‌زنی | عبور از NAT هر دو گوشی با معرفی ناظر، با UDP (QUIC) و TCP | بله |
| از راه ناظر (رله) | پشتیبان همیشگی: هر دو گوشی به ناظر وصل می‌شوند و ناظر بایت‌ها را جابه‌جا می‌کند | بله |
| پشتیبانی وای‌فای آگاه | آیا گوشی Wi-Fi Aware دارد و الان در دسترس است؛ چیزی نمی‌فرستد | نه |
| libp2p: گفت‌وگوی دو گوشی (بخش ۴) | پیدا کردن هم از راه Kademlia خصوصی روی رلهٔ ناظر، اتصال از راه relay v2، اتصال مستقیم با DCUtR؛ پیام کوچک و ۱ مگابایت روی هر راه. کارت گوشی لازم نیست | بله (ناظر نسخهٔ جدید) |
| iroh: گفت‌وگوی دو گوشی (بخش ۴) | رلهٔ خود iroh روی ناظر و میز معرفی؛ اتصال از راه رله و بعد مسیر مستقیم؛ همان سنجش‌ها | بله (ناظر نسخهٔ جدید) |
| بلوتوث: سرعت و برد (بخش ۵) | اتصال GATT، دست‌دادن Noise، رفت‌وبرگشت، ۶۴ کیلوبایت هر طرف، و حالت برد (هر ثانیه یک پیام و قدرت سیگنال) | نه؛ کارت هر دو گوشی لازم است |
| باتری (بخش ۵) | یک ساعت سرویس پیش‌زمینه با اتصال زندهٔ libp2p به ناظر؛ سطح و شمارندهٔ باتری پیش و پس | بله |
| هزینهٔ TLS پساکوانتومی (بخش ۶) | ۱۰۰ دست‌دادن TLS 1.3 در حافظه با X25519 و با X25519MLKEM768 | نه؛ اینترنت هم لازم نیست |

هر راهی که وصل شود اندازه گرفته می‌شود: ۱۰ رفت‌وبرگشت و ۱ مگابایت در هر جهت (در بخش ۴: یک پیام و ۱ مگابایت).

بلوتوث روی اندروید ۱۱ و پایین‌تر بدون «موقعیت مکانی» روشن نمی‌تواند جست‌وجو کند؛ برنامه همان اول این را می‌گوید.

## رمزنگاری (ت۱۸)

- **گوشی و ناظر:** `Noise_NK_25519_ChaChaPoly_BLAKE2s` با کتابخانهٔ snow؛ کلید ناظر از کارت ناظر می‌آید.
- **دو گوشی روی TCP:** TLS 1.3 (rustls) با گواهی تازه برای هر جلسه. اثر SHA-256 گواهی در کارت گوشی است و گوشی دیگر فقط همان گواهی را می‌پذیرد. SNI فرستاده نمی‌شود.
- **دو گوشی روی UDP:** QUIC (quinn)، که TLS 1.3 را درون خودش دارد، با همان گواهی.
- **رله:** دو گوشی TLS 1.3 سرتاسری دارند؛ ناظر فقط دادهٔ رمزشده می‌بیند.
- **libp2p:** Noise (`/noise`) روی TCP و QUIC؛ رله فقط دادهٔ رمزشده جابه‌جا می‌کند.
- **iroh:** QUIC با TLS 1.3 بین دو گوشی؛ تا رلهٔ ناظر TLS که گواهی‌اش با اثر SHA-256 در کارت ناظر پین شده است.
- **بلوتوث:** `Noise_NKpsk0_25519_ChaChaPoly_BLAKE2s` با کلید و رمز مشترک کارت گوشی سرور؛ هر بسته نونس دارد و تکراری‌ها رد می‌شوند. تبلیغ بلوتوث فقط شناسهٔ سرویس و ۶ بایت تصادفی از شناسهٔ جلسه را دارد.
- **TLS پساکوانتومی:** از گوشی بیرون نمی‌رود؛ هر دو طرف دست‌دادن داخل خود برنامه‌اند.
- **بسته‌های بی‌محتوا:** بسته‌هایی که برای باز کردن NAT یا آزمون پالایش فرستاده می‌شوند فقط بایت تصادفی‌اند (۱۲ یا ۱۶ بایت) و هیچ داده‌ای ندارند.
- **تنها استثنا، UPnP:** پروتکل UPnP رمز ندارد. این آزمون فقط با زدن دکمه و پس از هشدار اجرا می‌شود، فقط داخل شبکهٔ خانه با مودم حرف می‌زند، و فقط نشانی محلی گوشی، شمارهٔ دو درگاه و برچسب «netprobe» را می‌فرستد. درگاه‌ها بلافاصله بسته می‌شوند. برای خود MLM CHAT، این استثنا باید در جدول «هر داده چطور رمز می‌شود» (بند ۹ برنامه) تصمیم بگیرد.
- هیچ رمزنگاری دست‌سازی در کار نیست؛ همه از snow، rustls، quinn، ring، aws-lc-rs، libp2p و iroh است.

## حریم خصوصی گزارش

گزارش (`netprobe-report/1`) هیچ نشانی IP، کلید یا کارتی ندارد. هر نشانی با برچسبی مثل `v4-public#2` جایگزین می‌شود؛ پس هنوز معلوم است «دو ناظر یک نشانی عمومی دیدند» یا نه، ولی نه اینکه کدام نشانی. شناسهٔ جلسه (عدد تصادفی) در گزارش می‌ماند تا گزارش دو گوشی با هم جفت شود.

## ساخت

```powershell
.\build-netprobe.ps1               # libnetprobe.so برای چهار معماری + APK
.\build-netprobe.ps1 -SkipNative   # فقط APK
```

- فایل نصبی: `app\build\outputs\apk\debug\app-debug.apk`
- کتابخانهٔ بومی از `native/` (پل JNI) و `../probe-core/` (همهٔ سنجش‌ها) با cargo-ndk ساخته می‌شود، برای arm64-v8a، armeabi-v7a، x86 و x86_64، با هم‌ترازی ۱۶ کیلوبایت (`native/.cargo/config.toml`). `..\check-so.ps1 app\src\main\jniLibs` حجم و هم‌ترازی را نشان می‌دهد.
- سه کتابخانهٔ دیگر فقط برای arm64-v8a و armeabi-v7a: `libspike_libp2p.so` (`../spike-libp2p`)، `libspike_iroh.so` (`../spike-iroh`) و `libspike_pqtls.so` (`../spike-pqtls`). روی معماری دیگر، دکمه‌هایشان می‌گوید کتابخانه بار نشد.
- اگر DNS این رایانه ناپایدار است: پیش از اسکریپت `$env:CARGO_NET_OFFLINE="true"`.
- نیازها روی این رایانه: Rust روی `I:\` (`CARGO_HOME=I:\cargo`، `RUSTUP_HOME=I:\rustup`)، cargo-ndk، NDK r27d در `I:\Android\ndk\android-ndk-r27d`، و JBR اندروید استودیو.

## نصب

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

یا فایل APK را به گوشی بفرستید و نصب کنید. اجازه‌ها: دوربین (برای خواندن QR)، و برای بلوتوث: «دستگاه‌های نزدیک» روی اندروید ۱۲ و بالاتر، یا «موقعیت مکانی» روی اندروید ۱۱ و پایین‌تر؛ هر دو فقط وقتی دکمهٔ بلوتوث زده شود خواسته می‌شوند. برنامه اینترنت و وضعیت شبکه را هم می‌خواهد که اجازهٔ جداگانه لازم ندارند.

## اجرا از رایانه با adb

همان کار دکمه‌ها؛ نتیجه در گزارش برنامه ثبت می‌شود و در logcat هم می‌آید (بی‌نشانی IP):

```bash
adb shell am start -n com.mlmchat.netprobe/.MainActivity --es observer "mlmobs1:..." --es run nat
adb logcat -s netprobe
```

`run` یکی از این‌هاست: `nat`، `obs_speed`، `upnp`، `make_card`، `aware`، `p2p_chat`، `iroh_chat`، `battery` (با `--ei seconds N`)، `pqtls` (با `--ei handshakes N`) و `ble` (با `--ei range_s N`). `--es peer "mlmnp1:..."` کارت گوشی دیگر را می‌گذارد.

دو گوشی با USB روی یک رایانه، بلوتوث بی‌دوربین: `bash scripts/ble-pair.sh SERIAL_A SERIAL_B [ثانیه‌های حالت برد]`. اسکریپت روی هر دو نصب می‌کند، کارت می‌سازد، کارت‌ها را جابه‌جا می‌کند و آزمون را روی هر دو شروع می‌کند. گوشی اول همیشه سرور است؛ گوشی اندروید ۱۱ با موقعیت خاموش را اول بدهید. کارت فقط در پوشهٔ خصوصی برنامه نوشته می‌شود (`run-as`)، نه در logcat.

## گزارش

- «فرستادن گزارش»: متن JSON را با هر پیام‌رسانی می‌فرستد.
- «ذخیرهٔ گزارش در پوشهٔ برنامه»: `Android/data/com.mlmchat.netprobe/files/reports/`، که با `adb pull` هم برداشته می‌شود.
- خلاصهٔ چند گزارش، به شکل ردیف‌های جدول `PHASE0-RESULTS`:

```bash
python -I scripts/summarize.py report-a.json report-b.json
```

## ساختار

| پوشه | چیست |
|---|---|
| `app/` | برنامهٔ گوشی (جاوا، بدون AndroidX؛ QR با zxing) |
| `native/` | پل JNI به `probe-core`، ساختهٔ cargo-ndk |
| `../probe-core/` | همهٔ سنجش‌ها و پروتکل گوشی و ناظر؛ با `probe-cli selftest` روی loopback آزموده می‌شود |
| `../observer/` | ناظر رایانهٔ خانگی |
| `scripts/summarize.py` | خلاصهٔ گزارش‌ها |
| `scripts/ble-pair.sh` | آزمون بلوتوث دو گوشی از رایانه |
| `../spike-libp2p/`، `../spike-iroh/`، `../spike-pqtls/` | کتابخانه‌های بخش‌های ۴ تا ۶؛ رله‌های libp2p و iroh داخل `../observer/` اجرا می‌شوند |
